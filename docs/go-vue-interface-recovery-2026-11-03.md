# Go + Vue 接口阻塞修复（2026-11-03）

范围：`boer-lan-server/backend`。未修改 Vue 页面或 Qt 实现，未操作客户正在运行的系统。

## 问题与改动

- v1.0.34 将连接池限制为 8 个；v1.0.35 的驱动内写队列仍先占连接再排队。旧版配置的对照复现中，持有一个写事务并排队七个写入时，v1.0.33 查询成功，v1.0.34 和 v1.0.35+ 查询超时。
- 新增 GORM 连接池适配层：8 个查询连接、1 个写连接；普通写入及事务先经过带优先级、有界的队列，再获取写连接。生产事务保留高优先级，取消的事务会释放队列许可。原始 SQL 的返回结果和预编译写语句仍由单连接写池串行执行。
- 设备树与分组读取原先总会执行一次分组 UPDATE，即使没有待归并分组也占写锁。现在先查询是否确有需要归并的分组，正常轮询不再提交无用更新。保留旧分组修复行为。
- 历史补算保留调用方取消信号，每条事务最多两秒、每条完成后短暂让路、每批 50 条保存进度。现存工资字段相同则不 UPDATE。
- 补算进度保存于 `server_configs.production_backfill_cursor_v1`；成功扫描的历史范围不再每次启动重放。缺失设备的历史记录保留并跳过；其他事务失败时不越过失败记录。取消时至多重放尚未保存进度的一批，仍通过来源 ID 去重。此进度属于这次历史修复版本；若需重新执行全量历史补全，可在停机维护时重置此键，未来修复算法变化应升级键名。
- 调试日志通过有界队列后台批量写入，降低优先级并限定时间。压力过大时可跳过数据库中的调试副本；文件日志继续保存，生产记录不走这条可丢弃队列。
- 正常退出及测试清理会关闭查询、写入两组连接。

## 验证

- `go test ./...`：全部通过（完整测试需要本机回环监听权限）。
- 针对新连接池、队列优先级、取消、历史进度、日志、生产入库及 ACK 的 `go test -race`：通过。
- 32 个事务排队时，查询成功；释放占用事务后 33 条预期写入全部存在。
- 16 个并发上传任务，共 128 条生产记录，每条重复发送一次，同时执行 200 次查询：生产记录和工资各 128 条，没有重复计件或丢失。
- 写锁占用期间发送 100 条调试日志：调用不等待数据库；释放写锁后数据库副本完成写入。
- 设备列表、设备树、用户信息在 64 个写入任务积压时的接口回归加入默认测试。
- 客户 `1103` 数据库及 WAL 复制到测试临时目录，原始文件仅用于复制。副本 `PRAGMA quick_check` 通过。64 个写入排队时，实际接口调用分别约 1.58ms、1.05ms、0.20ms，后续 65 条预期写入全部存在；历史补算能够响应取消。
- 本机 Go 后端编译通过。
