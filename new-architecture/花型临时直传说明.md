# 花型临时直传（2.1.10）

这是原有上传功能之外的新模式。需要同时安装本版本的 Qt 客户端和 Qt 服务端；旧版或其他服务端没有该接口，客户端将明确提示升级，不会自动转为上传花型库。

## 使用

在花型文件页面点击上传，选择文件，将“上传方式”切换为“直接下发到机器（不留存）”，确认花型名称后选择目标设备，点击开始下发。支持多个文件和多个设备，按文件/设备组合顺序传输；一次最多 100 项。弹窗显示上传和机器下发进度，收到机器最终写入确认后才显示完成。可以取消剩余传输，已经写入机器的文件不会回滚删除。

默认仍为“上传到服务器”，原有花型库、下发队列和日志功能保持原来的使用方式。

## 数据与限制

链路为 Qt 客户端 → Qt 服务端 → 机器，复用现有 DT 花型下发协议。这里的“直接”指跳过服务端花型库，并非客户端直接连接机器。

直传内容和状态只放在服务端内存，不创建服务端花型文件、花型库记录、下发任务或下发日志；直传 HTTP 接口也不写访问日志。正常的设备连接状态更新和后续设备花型目录查询仍按原功能运行，不受直传模式影响。

成功、失败或取消后释放传输文件内容，客户端删除临时状态。客户端异常退出或失联时，服务端在最后一次查询后约 60 秒取消；终态状态保留最多约 60 秒。单次机器传输总时限为 10 分钟。重启服务端会丢失临时任务，需重新操作。

设备必须在线且空闲；正在缝纫、正在其他传输/目录查询/删除操作时明确返回失败，不进入持久化等待队列。取消或传输错误可能断开当前设备连接以终止 DT 会话，设备按原有机制重连。

设备协议限制：单文件不超过 16,711,680 字节（255 × 65,536），名称不超过 22 个 UTF-16 编码单元，不允许路径分隔符及控制字符。扩展名与现有服务端相同：slw、xdg、nsp、ntp、mtp、sdt、vdt、sdg、dst。服务端最多同时 8 个直传，活动内容总计最多 64 MiB，最多保留 128 个临时状态。

## 接口

使用现有登录令牌和花型文件权限校验。任务仅发起用户可以查询和取消。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/pattern/direct-upload` | multipart 字段 file、name、deviceId；返回临时 id、status、progress、message |
| GET | `/api/pattern/direct-transfer/<id>` | 查询状态；downloading、completed、failed |
| DELETE | `/api/pattern/direct-transfer/<id>` | 取消活动传输并删除状态，或清理已结束状态 |

POST 限制请求体 17 MiB。旧服务端返回 404/405 时客户端提示先升级 Qt 服务端；设备离线、忙碌或协议参数错误返回 409。临时状态失效或不属于当前用户返回 404。

## 验证

服务端端到端测试：

```sh
python3 server/tests/direct_transfer_cases.py /绝对路径/boer-qt-server
```

测试启动隔离的服务端、数据库和模拟 DT 机器，验证逐字节内容、分帧重发、最终写入确认、失败/取消/失联清理、权限隔离、文件及数据库无留存、HTTP 日志过滤，以及原有持久化上传和下发。

客户端 CTest `direct_pattern` 使用真实 Qt 弹窗和本机 HTTP 模拟服务，验证多设备顺序发送、完成/失败进度、清理、取消、双语以及旧服务端提示。`ui_smoke` 验证上传模式切换和原有表单。

模拟协议测试不代替现场 Windows 和机器实测。现场应验证目标机型的接收、写入、取消后重连及实际花型打开。
