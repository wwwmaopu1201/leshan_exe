# Qt 客户端开发交接与注意事项

> 基于当前 `new-architecture` 的 Qt/C++ 服务端与[原生客户端](client/README.md)整理。接口、能力和样式以代码及联调结果为准。本目录仍是独立实现，不等同于现有 Go/Tauri 产品的完整验收版本。VNC 按本阶段约定暂不纳入。

## 1. 先认清边界

| 部分 | 当前代码 | 客户端应如何使用 |
| --- | --- | --- |
| HTTP API | [api_server.cpp](server/src/api_server.cpp) | 客户端通过 HTTP 请求登录、账号、设备、分组等数据。不要直接访问服务端主数据库。 |
| 设备 TCP | [device_server.cpp](server/src/device_server.cpp) | 这是设备与服务端的 `DT` 协议端口，普通管理客户端不要拿它当业务 API。 |
| 主数据库与认证 | [database.cpp](server/src/database.cpp) | 新建部署可选择 SQLite 或 MySQL 主库；数据库、密码哈希和 JWT 密钥由服务端持有，客户端仅保存自身需要的会话状态。 |
| 服务端管理界面 | [main_window.cpp](server/src/main_window.cpp)、[editor_dialog.cpp](server/src/editor_dialog.cpp) | 可借鉴和提取原生 Qt 控件、样式与交互，但不要把服务端页面或数据库操作直接搬进客户端。 |
| 旧版参考 | [现有客户端 API](../boer-lan-client/src/api/auth.js)、[现有服务端页面](../boer-lan-server/src/views/Layout.vue) | 用来核对功能、文案和视觉效果；Qt 实现仍须保持原生。 |

默认 HTTP 端口为 `8088`，设备 TCP 端口为 `38400`。它们是两个服务，不能混用。同机运行旧版和 Qt 版服务端时还要避免端口冲突。Qt 数据库与旧 Go 数据库**不是同一份兼容数据库**，不要让客户端假定二者可直接切换。

正式服务启动时会在 Qt 数据库旁维护独立的 `server-trial-state.json`，用于机器绑定及系统时间回拨检查。开发环境可用 `APP_ENV=development` 或 `BOERLAN_SKIP_TRIAL=1` 跳过；联调时使用临时数据库目录，不要复制正式状态文件。
macOS 不能把 `QSysInfo::machineHostName()` 用作唯一绑定依据：同一台机器可能在 `xxx.local` 与 `localhost` 间变化。当前服务端改用 `QSysInfo::machineUniqueId()` 的稳定值；旧状态仅在保存的主机名指纹能由本机 `LocalHostName` 核对时迁移，并保留首次使用时间和启动次数。排查“启动后立即退出”时先看数据库旁 `logs/server_日期.log`：`Trial validation failed` 表示授权校验，`bound address is already in use` 表示 8088 或 38400 已被进程占用。不要通过删除正式状态文件处理这两类问题。

## 2. 客户端首先要固定的 API 约定

- 基础路径是 `/api`。除 `GET /api/healthz`、`POST /api/auth/login`、仅本机可调用的防火墙接口及 `/uploads/...` 静态文件外，请求需要 `Authorization: Bearer <token>`。
- 常规写操作发送 `Content-Type: application/json`；头像和花型上传使用 `multipart/form-data` 的 `file` 字段。服务端接受 `Content-Length` 和 `Transfer-Encoding: chunked`；普通请求体上限为 256 MiB，花型上传会先流式写入临时文件，单文件和 ZIP 下载按块发送。响应后关闭连接；当前没有实时推送接口可供客户端依赖。
- 当前监听所有 IPv4 网卡，传输是普通 HTTP，且响应允许跨域访问。客户端联调要明确连接的服务器地址；正式部署前应单独评估传输与网络边界，不能把这套原型的网络行为直接当作生产方案。
- 成功通常是 HTTP `200`，响应形如 `{"code":0,"message":"success","data":...}`；失败使用 HTTP `400/401/403/404/500`，`code` 为对应状态码并带 `message`。客户端要同时判断 HTTP 状态和 `code`，不要只看请求是否返回了 JSON。
- `POST /api/auth/login` 接收 `username`、`password`，可附 `clientVersion`；返回 `data.token`、`data.serverVersion`、`data.user`。Token 是 HS256 JWT，默认有效期 **24 小时**，服务端可通过 `jwt.expire` 或 `JWT_EXPIRE` 配置；没有续期接口。`POST /api/auth/logout` 当前只返回成功，不会撤销服务端已签发的 token；客户端退出时必须清除本地 token。
- `401` 表示未认证或 token 失效，应清除会话并回登录页；`403` 表示已认证但权限不足或账号被禁用，不要把所有 `403` 都误当密码错误。服务端错误文案当前可能是中文，英文界面需要客户端在展示层翻译固定文案。
- 客户端用可配置的服务器 IP/端口连接，而不是写死 `localhost`。旧客户端已有 `clientVersion` 上报、Bearer 请求拦截和错误处理，可作为对照，见 [auth.js](../boer-lan-client/src/api/auth.js)、[request.js](../boer-lan-client/src/api/request.js)。

### 已实现的主要路径

| 路径 | 当前返回/用途 | 接入注意 |
| --- | --- | --- |
| `/auth/login`、`/auth/userinfo`、`/auth/password`、`/auth/profile`、`/auth/logout` | 登录、当前用户、密码/资料、退出 | GUI 登录只允许管理员进入服务端管理窗口；HTTP 登录允许普通账号，再由接口权限控制。两者不要混为一谈。 |
| `/auth/login-logs` | `{list,total,page,pageSize}` | 管理员看全部，普通用户只看自己的记录；支持关键词、状态和日期筛选，登录 IP 已记录。 |
| `/auth/avatar` | 上传头像，返回 `data.avatar` | multipart `file`，限制 png/jpg/jpeg/webp 且不超过 2 MiB；返回的 `/uploads/avatars/...` 路径可直接读取。 |
| `/group`、`/role`、`/user`、`/operator`、`/device`、`/employee`、`/pattern` | 各实体的列表/详情与已实现写操作 | 花型新增必须走文件上传接口；设备普通删除为移出分组，`hard` 路径才软删除。 |
| `/pattern/upload`、`/pattern/:id/file`、`/pattern/files/download` | 服务器花型上传、单文件和 ZIP 下载 | multipart 上传；ZIP 下载返回二进制，不按 JSON 解包。 |
| `/pattern/download`、`/pattern/queue`、`/pattern/device-files`、`/pattern/upload-queue` | 下发、设备文件刷新/删除、回传与双向队列 | 已接入 DT 协议工作器；真实设备的全部重试、冲突及断线边界仍需联调。 |
| `/employee/import`、`/employee/export`、`/operator/import`、`/operator/export` | JSON 批量导入和导出 | 导入逐条返回成功数及错误列表；导出返回 JSON 数组。 |
| `/statistics/home`、`/statistics/dashboard`、`/statistics/production-trend`、`/statistics/salary`、`/statistics/salary/detail`、`/statistics/alarm`、`/statistics/process`、`/statistics/duration`、`/statistics/device-patterns`、`/statistics/export/:type` | 设备、生产、工资、报警、加工、时长统计及 CSV 导出 | CSV 返回二进制；复杂历史工时、员工归属和价格追溯仍需与旧版逐项校验。 |
| `/group/tree`、`/device/tree`、`/device/groups`、`/employee/groups` | 分组和设备树 | 设备树还包含 `id="ungrouped"`、`id="all"` 的**虚拟节点**；树节点 ID 不全是数字。 |
| `/device/types`、`/device/electric-control-types`、`/pattern/types` 及对应 `*-summary` | 类型目录及数量 | `GET` 普通类型路径返回字符串数组，summary 返回对象数组；新增/改名/删除走 summary 路径。 |
| `/device/move`、`/user/move`、`/operator/move`、`/group/sort` | 批量移动、分组排序 | 请求体字段不同，分别是 `deviceIds`、`userIds`、`operatorIds`；目标分组用 `groupId`。 |
| `/system/info`、`/system/stats`、`/system/network`、`/system/ping`、`/system/command`、`/system/logs`、`/system/config` | 管理信息、诊断、调试日志及配置读写 | 仅管理员可用；配置写入已支持，监听端口仍需重启进程才能修改。 |
| `/system/database/*`、`/system/firewall/*` | 外部库配置/测试/同步状态与本机防火墙状态/修复 | 外部库需要 QMYSQL/QODBC 插件；防火墙修复只允许服务端本机调用，Windows 下触发 UAC。 |

列表返回形态目前**并不统一**：`device`、`employee`、`pattern` 的列表返回 `{list,total,page,pageSize}`，并接受 `page/pageSize`；`group`、`role`、`user`、`operator` 的普通列表返回数组。客户端应在 API 层分别解包，统一成页面使用的分页模型，不要在表格组件里猜响应形态。

## 3. 字段、权限和数据原文

- 主库字段由服务端转成驼峰 JSON；部分响应还带兼容别名，例如 `id/ID`、`createdAt/CreatedAt/createTime`、`modelName/model`。客户端选定一种内部 DTO 命名并集中归一化，不要在各页面交替使用别名。
- `permissions` 在数据库和若干响应中是 **JSON 字符串**，不是总能直接当对象使用。`groupIds` 在登录响应的 `user` 中会被转成数组，而 `userinfo` 等数据库行响应可能仍是 JSON 字符串。客户端应容忍两种输入并归一化为确定类型。
- 未分组使用 JSON `null` 作为 `groupId`；不要把 `0`、空字符串和 `null` 随意混用。当前旧 Go 与 Qt 服务端都将账号分组用于组织管理，业务数据可见性由角色权限决定，**不按账号所属分组过滤**。普通账号仍不能调用用户/角色等管理接口；展开细分权限后，父权限不自动授予未勾选的子权限。
- **用户填写的数据必须显示和保存原文。** 中文账号姓名、角色名、备注、设备名、分组名、目录值，即使切到英文也不应自动译成英文。只翻译固定标签、按钮、状态枚举和提示语。Qt 服务端为此给数据项设置 `UiI18n::PreserveDataRole`，并在需要保存下拉项时通过 `UiI18n::sourceText()` 获取原值，见 [ui_i18n.h](server/src/ui_i18n.h)。客户端应沿用这个边界。
- `status` 等固定枚举可以本地化展示，但请求和业务判断仍使用服务端原值。状态标签的**宽度要按译后文本重新测量**；登录日志里的 `失败`→`Failed` 曾让红色标签截断，现有服务端表格已按文本调整标签及列宽。
- 当前 `/system/info` 的 `uptime` 实际写入的是当前 Unix 秒数，不是运行时长。客户端不要直接把它当“已运行秒数”显示，待接口修正后再使用。

## 5. 这次服务端 UI 开发踩过的坑

1. **复选框大小与点击：** 勾选/未勾选的外框尺寸必须一致；勾选图标要完整填色。此前普通复选框与树/表格指示器依赖 QSS 边框和 SVG 图像，在 Windows 下出现过外框缺失、选中态错误；现统一通过 `UiCheckboxStyle` 的 Qt 绘制处理两类指示器，客户端复用时也要在 Windows 实机检查。表格批量选择用独立 `QCheckBox`，不要让快速点击被单元格双击/焦点逻辑吞掉。行选中和批量勾选是两种状态。
2. **树与列表：** 权限名、可见分组名点击后要切换勾选，不要只高亮一小块文本。可见分组应按“总分组 → 子分组 → 下级子分组”的树形结构展示并逐项勾选；序列化时递归读取所有树节点。处理鼠标事件时先记录旧状态，交给 Qt 处理后只在状态未变时手动切换，避免点原生复选框被切两次。
3. **局部滚动：** 展开细分权限时固定外层弹窗和字体尺寸，让权限框内部滚动。其他长表单可以有外层滚动，但避免出现无意的水平滚动条。
4. **响应式与英文长度：** 英文标签、菜单项、状态值往往更长。账号/设备页的顶部筛选**不是固定两行**：宽度足够时自动排成一行，缩窄或切换到更长英文文案后再按“标签＋控件”整体换成两行；尺寸恢复时应自动回到一行。工具栏在窄窗口可分两行；权限标签按顺序紧贴排列、空间不够才换行，不做固定网格；状态 pill、表头和列宽按实际文本测量。至少检查 `1600×1000` 与 `1120×700` 两种窗口，并验证来回缩放。
5. **下拉框：** Qt 默认弹出层位置和行高不一定符合设计。除贴合控件下方，还要在显示前重算 item layout，确认所有选项可见、每行可点且行高与输入框相符。
6. **高分屏图标：** 避免用普通 Unicode 字符冒充图标；SVG、字体图标或 `QPainter` 绘制要考虑 device pixel ratio。空列表图标、日历、箭头都要在实际高分屏上看清。
7. **反馈与登录错误：** 刷新等短操作应明确显示已完成；成功提示采用与原 Vue 接近的浅绿色、顶部居中提示，**不加前置对勾**。登录失败等可恢复错误使用顶部居中的红色非模态消息，**保持登录表单可见、可继续输入，不再弹单独的 `QMessageBox` 窗口**。网络/文件等长操作应异步执行，不要阻塞 Qt 主线程；服务端现有 `runTool()` 使用同步等待，客户端不要照搬。
8. **翻译边界：** 静态 UI 可翻译，数据库数据不可翻译。中英切换后要检查编辑表单中的原文、下拉选项的保存值、动态提示和嵌套权限条目。只翻译登录页而遗漏主界面曾是实际问题。
9. **样式作用域：** 当前 [theme.qss](server/assets/theme.qss) 包含全局 `QPushButton`、`QLineEdit` 等选择器。抽成公共主题时，要检查客户端新弹窗是否被全局规则影响；控件专属外观尽量用 `objectName` 限定。
10. **所有弹窗与右键菜单：** 对照原 Vue 的层级、留白、按钮、遮罩和校验样式实现；不要直接把 Qt 默认 `QInputDialog`、`QMessageBox` 或系统菜单放进成品界面。所有业务弹窗统一通过 `UiModalDialog::attach` 设为应用级模态；macOS Cocoa 下弹窗期间锁定原主窗口的标题栏拖动和窗口按钮，关闭后恢复。**不要使用 `NSWindow.ignoresMouseEvents` 来禁用主窗口**，那会让点击穿透到后面的窗口或桌面。遮罩挂在 `parent->window()` 上并覆盖包括左侧菜单的整个主窗口，由遮罩拦截内容点击；没有现成遮罩的弹窗由公共模态守卫补齐。表单内容与滚动视口保持白底，外层禁止无意的水平滚动。新增/重命名子分组使用与其他编辑表单一致的标题、输入、底部按钮和内联校验；右键菜单按 Vue 的白底、浅边框、悬停色与间距统一。新弹窗也要检查中英文与小窗口效果。
11. **客户端表格、下拉框与导出：** 表格需要有一列随窗口宽度伸展；固定操作列按当前语言的实际按钮文字计算宽度，不得留白断层或挤压按钮。点击数据行应同步切换该行复选框，点击独立操作按钮不改变勾选。控件高度按服务端场景分别对齐：普通筛选框约 28 像素，登录框和编辑弹窗输入框约 36 像素；不要把弹窗的高度规则应用到所有页面。客户端普通下拉框和登录页 `QCompleter` 联想弹层都要让选项行与对应输入框同高，弹层紧贴控件下方并显示完整选项；这两种弹层需要分别处理。写着“导出 Excel”的按钮必须生成可打开的 `.xlsx`，不能仅把 CSV 改名为 Excel。
12. **导入导出与文件下载：** 页面按钮必须真正打开可见的文件选择/保存窗口，确认路径后要有即时“正在处理”反馈，并最终报告成功或可读的失败原因。客户端统一通过 `ClientFileDialog` 打开 Qt 文件窗口；覆盖单文件、批量文件、保存文件以及表单里再次打开文件窗口的嵌套场景。端到端测试必须从页面按钮触发，验证写出的文件或导入后的记录，不能只测绕过界面的 HTTP 接口。

## 6. 当前缺口：规划客户端页面前逐项核对

Qt 服务端已接入设备花型双向传输、队列工作器、设备文件列表与删除、原生花型管理/统计页面、加工/时长/设备花型统计及 CSV 导出。新建主库现可配置 MySQL，接口统计支持多设备筛选和缺失时间补算，设备列表与回传队列可自动刷新。仍需在真实设备上验证少见的协议恢复与身份匹配，在有 QMYSQL/QODBC 驱动的环境验证主库及外部 MySQL/MSSQL，并在 Windows 验证防火墙 UAC 修复。旧数据库和 bcrypt 密码迁移按本次约定暂不处理。

原生客户端当前已接入非 VNC 页面；远程监控页保留设备状态、报警和趋势数据，仅跳过 VNC 画面与控制。客户端已在临时服务端做过页面、登录、目录增改删和花型上传下载联调。尚未经过真实设备或外部数据库联调的动作仍要明确标记验证状态，不要把模拟设备通过等同于现场可用。当前 Qt 服务端不保证与旧 Go 服务端逐项兼容，尤其不能直接用旧 bcrypt 哈希数据登录 Qt 数据库。

## 7. 建议的客户端实现顺序与验收

1. 先提取不依赖服务端业务的 Qt 公共控件、主题、图标和翻译层；让两端使用同一套控件行为。
2. 建立异步 HTTP 客户端：统一 base URL、JSON 解包、Bearer token、超时、`401/403` 处理和分页适配。不要在按钮回调里同步等待网络。
3. 完成登录、当前用户和角色细分权限，再按“已实现接口清单”逐页接入。保存原始业务值，界面展示值与请求值分离。
4. 用独立测试数据库和非正式端口联调，不对正式数据库执行破坏性测试。先运行 `ctest --test-dir new-architecture/server/build --output-on-failure`；API 与设备协议的可执行示例见 [api_smoke.py](server/tests/api_smoke.py)、[tcp_smoke.py](server/tests/tcp_smoke.py)。
5. 对每个页面做中文、英文、不同窗口尺寸及有数据/无数据检查；重点复查可编辑中文内容是否保持原文、弹窗展开/滚动、快速勾选、状态标签和较长下拉选项。

当前 Mac 一键启动脚本 [start-server.command](start-server.command) 使用正式 Qt 数据库并占用 `8088/38400`，不适合作为客户端自动测试入口。Windows `.exe` 应在 Windows 本机或 GitHub Actions 的 Windows runner 上构建，并打包实际用到的 Qt DLL/插件；Mac 构建产物本身不能当 Windows 客户端或服务端 `.exe` 使用。
